# PCB design with KiCad

This project includes PCB design work, done with KiCad from the command line.

The board design and its decisions are in `docs/design.md`, and the parts list is in
`docs/bom.md`. Keep both up to date when the design changes.

**Constraint: the user hand-solders everything.** Use through-hole parts (DIP chips, axial
resistors, leaded capacitors). Don't use SMD unless the user agrees.

## Tools on this machine

- **KiCad 10.0.8**: `kicad-cli` and the `pcbnew` Python module (`python3 -c "import pcbnew"`).
- **Libraries**: `/usr/share/kicad/{symbols,footprints,3dmodels}`.
- **Freerouting**: `~/bin/freerouting` for autorouting (export DSN, route, import SES).
- **Rasterizing**: `pdftoppm` works. `rsvg-convert` is not installed, and ImageMagick's
  SVG conversion fails (its inkscape delegate crashes), so go through PDF, not SVG.

## Looking at the board

The board can be checked visually by exporting images and opening the PNGs with the Read tool.
Do this after placement and after routing, not just at the end.

3D render of the assembled board (fast, about 0.3 s). Good for placement, silkscreen,
connector overhang and part clearances:

```sh
kicad-cli pcb render board.kicad_pcb -o render.png --width 1200 --height 900 --side top
# --side bottom for the underside
```

Flat layer plot, for checking routing:

```sh
kicad-cli pcb export pdf board.kicad_pcb -o layers.pdf \
  --layers F.Cu,B.Cu,Edge.Cuts --mode-single
pdftoppm -png -r 150 -singlefile layers.pdf layers   # writes layers.png
```

Notes:
- `--mode-single` is needed on KiCad 10. Without it the PDF export fails to write the file.
- A filled ground pour hides the traces. When checking routes, plot one copper layer at a
  time or plot before filling zones.
- At full-board size, fine clearances can't be judged by eye. Zoom in (higher `-r`, then
  crop) on dense areas, and rely on DRC for exact numbers.
- Put render output in the session scratchpad, not in the project.

Schematic plot:

```sh
kicad-cli sch export pdf pcb/footswitch.kicad_sch -o sch.pdf
pdftoppm -png -r 110 -singlefile sch.pdf sch       # whole A3 sheet
pdftoppm -png -r 220 -x X -y Y -W W -H H -singlefile sch.pdf crop   # zoom on a region
```

## Project layout

- `pcb/`: the KiCad project (`footswitch.kicad_pro`, `.kicad_sch`, later `.kicad_pcb`).
- `pcb/footswitches.pretty/`: project footprints (the PBS24-202P footswitch), registered in
  `pcb/fp-lib-table` as `footswitches`.
- The schematic was first generated by a script, but the `.kicad_sch` file is now the source
  of truth. Edit it in KiCad or as an S-expression file.
- The `pcbnew` Python module segfaults on any board or footprint load outside the GUI
  (`LoadBoard`, `FootprintLoad`, even `SETTINGS_MANAGER()`). Don't use it. To check that a
  footprint parses, run `kicad-cli fp upgrade <lib>.pretty -o <tmpdir> --force`.
- `pcb/scripts/` writes the files as S-expressions instead:
  - `gen.py` writes the schematic.
  - `pcbgen.py` writes the board from the netlist and a placement table, plus a Specctra DSN
    for Freerouting.
  - `sesimport.py` turns Freerouting's SES into tracks and vias.
  - `run.sh WORKDIR` runs the whole chain: board, routing, zone fill and DRC. The result is
    `WORKDIR/footswitch_drc.kicad_pcb`; copy it to `pcb/` when happy.
  - These scripts regenerate everything from scratch, so they discard edits made in KiCad.
    Check with the user before regenerating once they have edited the files by hand.
  - kicad-cli has no DSN export or SES import, which is why the scripts do that themselves.
- Freerouting: run the jar with the system Java
  (`java -jar ~/Downloads/freerouting-2.1.0-linux-x64/lib/app/freerouting-executable.jar`).
  The bundled runtime lacks `java.management` and pops up a `NoClassDefFoundError`.
  - Unset `DISPLAY` and pass `--gui.enabled=false`.
  - `-mp` is ignored; use `--router.max_passes=N`.
  - It only writes the SES when it finishes, so don't kill it on a timeout.
- Zones are filled with `kicad-cli pcb drc --refill-zones --save-board`.
- If the user has the project open in KiCad (`~*.lck` files in `pcb/`), tell them before
  rewriting a file they have open: saving from KiCad would overwrite your changes.

## Checks

```sh
kicad-cli sch erc board.kicad_sch -o erc.rpt
kicad-cli pcb drc board.kicad_pcb -o drc.rpt --schematic-parity
```

Fix everything ERC and DRC report before generating fab output. The user should still open the
board in KiCad for a final look before ordering.
